# ÜiirmeHub Pulse v3 — GitHub Pages + GitHub Actions

Монитор доступности `https://clubium-render.onrender.com/` с графиком, настоящими HTTP-кодами и публичной историей проверок в GitHub. Интерфейс адаптирован под телефон, выполнен одним `index.html` и не требует библиотек.

## Как установить — 5 шагов

1. Создайте **отдельный публичный репозиторий** GitHub, например `uiirmehub-pulse`. **Не добавляйте** файлы монитора поверх кода основного приложения `clubium-render`.
2. Загрузите **все файлы и папки из ZIP в корень** нового репозитория. Важно: папка `.github/workflows` должна сохраниться. Если загружаете через сайт GitHub, распакуйте архив на ПК, затем перетащите в репозиторий содержимое папки; проверьте наличие `.github/workflows/monitor.yml`.
3. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Нажмите **Save**, если появится.
4. Откройте **Actions → ÜiirmeHub Pulse • HTTP check and deploy → Run workflow** (или дождитесь ближайшего автоматического запуска). Убедитесь, что workflow завершился успешно и на вкладке Pages появился адрес опубликованной страницы.
5. Откройте страницу. Данные появятся после первого успешного запуска Actions. Не требуется держать браузер открытым для фоновых проверок GitHub.

Если workflow не может сохранить `data/status.json`, проверьте **Settings → Actions → General → Workflow permissions** и разрешите `Read and write permissions`, если политика репозитория позволяет. В YAML уже запрошено `contents: write`.

## Где что хранится

- `index.html` — весь сайт, тёмная/светлая тема, панель, события, график, опрос каждые 30 секунд **только пока страница открыта и браузер активен**.
- `monitor/config.json` — общий URL сервера, тайм-аут, допустимые коды HTTP и длина истории. Поменяйте URL здесь через **GitHub → Edit file → Commit changes**, чтобы изменение стало общим для всех устройств. Это безопаснее, чем записывать GitHub-токен в HTML.
- `monitor/check.py` — независимая проверка HTTP от имени GitHub Actions, со стандартной библиотекой Python.
- `.github/workflows/monitor.yml` — запуск проверки **приблизительно раз в 5 минут**, запись в `data/status.json`, а затем публикация новой версии GitHub Pages.
- `data/status.json` — общий результат и последние 288 облачных проверок; все изменения коммитятся в GitHub. Публичный файл содержит только HTTP-код, задержку, время и обезличенную ошибку: **никаких ФИО/паролей/содержимого ответов**.
- Тема интерфейса и включение/отключение браузерного опроса — хранятся **только локально** в браузере, не отправляются в GitHub. Очистка в интерфейсе удаляет только локальные события.

## Как работают запросы

- **В браузере:** каждые 30 секунд выполняется `fetch` с `mode: 'cors'` без cookies, токенов и содержимого запроса. Это может создавать входящий трафик Render, но если сервер не отдаёт заголовок `Access-Control-Allow-Origin`, браузер **не может прочитать** HTTP-код. Не путайте такую ошибку браузера с недоступностью сервера.
- **В GitHub Actions:** независимый Python-процесс выполняет GET и читает настоящий HTTP-статус, даже без CORS и без открытой вкладки. Облачные показатели, график и журнал показывают **именно** эти проверки.
- **Расписание Actions:** минимум 5 минут, **не гарантируется по секундам**; GitHub может откладывать или пропускать запуски. В публичных репозиториях расписание может отключиться через 60 дней без активности. При отсутствии новых данных более 18 минут сайт показывает **«Данные устарели»**, а не ложный статус «Сервер работает».
- **Проверяем доступность URL, не здоровье базы данных.** Если нужен контроль БД, сделайте на Render отдельный публичный endpoint `/health`, который при исправной БД возвращает `HTTP 200`, а иначе `503`, не раскрывая никаких личных данных. Затем установите этот URL в `monitor/config.json`.

## Важно про бесплатный Render

В Render Free сервис засыпает после 15 минут без входящих запросов. Регулярные запросы могут предотвращать сон из-за простоя, но не предотвращают принудительные рестарты, ограничения и исчерпание 750 часов Free на workspace. Free имеет временную файловую систему: **не храните единственную копию важных данных учеников в локальной SQLite**. Используйте стойкое хранилище и регулярные проверенные резервные копии.

## Безопасность и ограничения

- **Не вставляйте GitHub PAT, API-ключи, пароли или сведения учеников в `index.html`**, `config.json`, `data/status.json` или git-историю: при публичном Pages они доступны всем.
- Запись в GitHub непосредственно из публичного HTML без отдельной защищённой авторизации невозможна. В этой версии общая история надёжно обновляется **после каждой облачной проверки** через `GITHUB_TOKEN` внутри GitHub Actions; действия с UI на GitHub прямо не записываются.
- Каждые 5 минут создаётся коммит истории и деплой Pages. Это относительно тяжёлый режим для GitHub. Для длительной эксплуатации предпочтительнее оплачиваемый always-on хостинг, специализированный мониторинг или более редкая запись истории (например, каждые 10 минут).
- GitHub Pages — статический хостинг и не выполняет фоновые процессы, когда никто не посещает страницу. Именно GitHub Actions запускает проверки на стороне GitHub.

## Тесты

```sh
python -m unittest discover -s tests -v
python -m json.tool data/status.json
```

Тесты не отправляют запросов на настоящий Render. Автоматизация начнёт делать запросы только после публикации репозитория и активации GitHub Actions.
